# 04. 디자인 시스템

첨부된 스크린샷 3장에서 **실제 픽셀값을 추출해** 만든 토큰이다.
`실측`은 스크린샷에서 직접 뽑은 값, `제안`은 실측값에서 파생시켰거나 스크린샷에
없어서 새로 정한 값이다.

## 4.1 원칙

1. **그림자를 쓰지 않는다.** 스크린샷의 모든 카드는 `1px` 보더로만 구분된다.
   그림자는 바텀시트·모달·FAB처럼 실제로 떠 있는 것에만 쓴다. 카드에 그림자를
   넣으면 리스트가 길어질 때 화면이 지저분해진다.
2. **배경은 카드가 아니라 페이지가 담당한다.** 페이지는 `#EEF2F9`, 카드는 순백.
   이 대비만으로 카드가 뜬 것처럼 보인다.
3. **숫자는 등폭으로 정렬한다.** 시간(`09:25 ~ 11:20`)과 금액(`¥4,600`)에
   `font-variant-numeric: tabular-nums`. 없으면 리스트에서 자릿수가 흔들려
   조잡해 보인다.
4. **색은 의미만 전달한다.** 카테고리 구분은 색 + 텍스트 라벨을 항상 함께 쓴다.
   색만으로 정보를 전달하는 곳을 만들지 않는다.
5. **`!important`를 쓰지 않는다.** 충돌은 구조와 선택자 특이도로 해결한다.
   유일한 예외 후보(`::view-transition` 오버라이드)도 CSS 변수로 우회한다
   ([05](05-motion-and-navigation.md) §5.6).

## 4.2 색상 토큰

### 표면과 텍스트

| 토큰 | 값 | 출처 | 용도 |
| --- | --- | --- | --- |
| `bg.app` | `#EEF2F9` | 실측 | 페이지 배경 |
| `bg.subtle` | `#F8FAFD` | 실측 | 섹션 구분 배경 |
| `bg.surface` | `#FFFFFF` | 실측 | 카드, 헤더, 시트 |
| `bg.muted` | `#F3F4F6` | 실측 | 중립 칩 배경 |
| `bg.pill` | `#F9FAFB` | 실측 | 도보시간 pill |
| `border.default` | `#E6E7EB` | 실측 | 카드 보더 (1px) |
| `border.subtle` | `#EDF1F8` | 실측 | 구분선, 스켈레톤 |
| `text.primary` | `#121826` | 실측 | 제목, 본문 |
| `text.strong` | `#394150` | 실측 | 칩·pill 텍스트 |
| `text.secondary` | `#6D727F` | 실측 | 메타, 설명, 비활성 탭 |

`#F3F4F6`, `#E6E7EB`, `#6D727F`는 Tailwind 기본 gray 스케일과 거의 일치한다
(`gray-100`, `gray-200`, `gray-500`). 원본 디자인이 그 스케일 위에서 만들어졌을
가능성이 높아서, 중립색을 확장할 때 Tailwind gray를 기준으로 삼으면 이질감이 없다.

### 강조와 상태

| 토큰 | 값 | 출처 | 용도 |
| --- | --- | --- | --- |
| `accent.primary` | `#3762E3` | 실측 | 활성 탭, 링크, 주요 버튼, 탭 인디케이터 |
| `accent.primaryPressed` | `#2C4FBA` | 제안 | 눌린 상태 |
| `money.text` | `#2E7D57` | **제안 (수정)** | 금액 텍스트 |
| `money.surface` | `#F3FDF5` | 실측 | 총비용 카드 배경 |
| `danger.solid` | `#C63F39` | **제안 (수정)** | 미배치 개수 배지 배경 |
| `warning.text` | `#8A5A16` | 제안 | 영업시간·시간충돌 경고 |
| `focus.ring` | `#3762E3` | 제안 | `:focus-visible` 링 (2px, offset 2px) |

**두 색을 실측값에서 바꿨다.** 스크린샷의 금액 초록 `#43946C`는 흰 배경에서
3.69:1, 빨간 배지 `#DD524C`는 흰 글자와 3.9:1로 **WCAG AA(4.5:1)에 미달한다.**
금액과 배지 숫자는 굵지만 15px/11px여서 large text 예외에도 해당하지 않는다.
`#2E7D57`(흰 배경 5.02:1, 초록 칩 배경 4.59:1, 총비용 카드 배경 4.82:1)과
`#C63F39`(흰 글자 5.03:1)로 올리면 색감은 거의 그대로 유지하면서 기준을 통과한다.

> 스크린샷 2·3번에서 활성화된 `지도`/`비용` 탭을 감싸고 있는 주황색 사각 테두리는
> 디자인 요소가 아니라 브라우저 기본 포커스 링으로 보인다. 이 시스템에서는
> `focus.ring` 토큰으로 대체하고, 기본 `outline`은 제거하지 않고 재정의한다
> (제거하면 키보드 사용자가 위치를 잃는다).

### 카테고리 팔레트

칩(배지)과 차트에서 같은 의미에 같은 색을 쓴다.

| 카테고리 | 칩 배경 | 칩 텍스트 | 차트 fill | 차트 라벨 텍스트 | 출처 |
| --- | --- | --- | --- | --- | --- |
| 관광 `sight` | `#F3E9FE` | `#6B2FBF` | `#9D5AEF` | `#9455E1` | fill 실측, 나머지 제안 |
| 교통 `transport` | `#E9F0FE` | `#1F4FC4` | `#4E81EE` | `#4573D4` | fill 실측, 나머지 제안 |
| 식사 `food` | `#E2FBE9` | `#2E7D57` | `#5EC26A` | `#408548` | 배경·fill 실측, 텍스트 제안 |
| 이동 `move` | `#F3F4F6` | `#394150` | `#6D727F` | `#6D727F` | 실측 |
| 쇼핑 `shop` | `#F9E8F3` | `#90264D` | `#C2568F` | `#BA5289` | 배경·텍스트 실측, fill 제안 |
| 카페 `cafe` | `#FDF2E3` | `#8A5A16` | `#DA9B35` | `#9B6E26` | 제안 (스크린샷에 칩 없음) |
| 숙소 `stay` | `#E6F5F7` | `#0E7490` | `#0E7490` | `#0E7490` | 제안 |

모든 칩 조합이 AA 이상이다 (4.59 ~ 9.33:1).

**파이차트의 한계를 알고 있어야 한다.** fill 색끼리의 대비는 1.02~2.15:1로
낮아서, 인접 슬라이스를 색만으로 구분하기 어렵다. 특히 관광(보라)과 쇼핑(핑크)은
1.02:1로 사실상 구분이 불가능하다. 보완책 세 가지를 모두 적용한다.

- 슬라이스 사이에 `2px` 흰색 stroke (스크린샷에도 이미 있다)
- 슬라이스마다 직접 라벨 + 퍼센트 표기 (스크린샷의 `식사 65%` 방식)
- 인접 순서를 색상환 거리로 정렬해 비슷한 색이 붙지 않게 배치

## 4.3 타이포그래피

```
font-family:
  'Pretendard Variable', Pretendard,
  -apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo',
  system-ui, 'Malgun Gothic', sans-serif;
```

한글은 플랫폼별 시스템 폰트 차이가 커서(iOS Apple SD Gothic Neo vs Android Roboto)
같은 레이아웃이 다르게 보인다. Pretendard를 서브셋으로 얹으면 이 편차가 사라진다.
비용은 가변 폰트 서브셋 약 30~60KB — 모바일에서 수용 가능한 범위다.

| 토큰 | 크기 / 행간 / 굵기 | 용도 |
| --- | --- | --- |
| `heading.lg` | 20 / 1.3 / 700 | 페이지 타이틀 (`나고야 여행 플래너`) |
| `heading.md` | 17 / 1.35 / 700 | 카드 제목 (`아츠타 호라이켄 마츠자카야점`) |
| `body` | 15 / 1.5 / 400 | 본문 |
| `label` | 13 / 1.4 / 600 | 시간 (`09:25 ~ 11:20`), 탭 라벨 |
| `caption` | 12 / 1.45 / 400 | 메타·설명 (`히츠마부시, 대기표 먼저 받기`) |
| `badge` | 11 / 1 / 600 | 카테고리 칩, 개수 배지 |
| `amount` | 15 / 1 / 700 | 금액. `tabular-nums` |
| `amount.lg` | 20 / 1 / 800 | 총비용. `tabular-nums` |

`caption`(12px)은 `text.secondary`와 조합 시 흰 배경에서 4.81:1로 통과하지만,
`bg.app`(#EEF2F9) 위에서는 4.29:1로 미달한다. **12px 회색 텍스트는 흰 카드 안에만
쓴다.** 페이지 배경 위에 놓아야 하면 `text.strong`으로 올린다.

4px 배수 스케일.


| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `radius.sm` | 8px | 칩, 작은 버튼 |
| `radius.md` | 12px | 카드 |
| `radius.lg` | 16px | 바텀시트 상단, 패널 |

| 그림자 | 값 | 용도 |
| --- | --- | --- |

카드에는 그림자 토큰이 없다. 의도적이다(§4.1).

## 4.5 레이아웃

```
┌─────────────────────────────┐  bg.app (#EEF2F9)
│ ┌─────────────────────────┐ │
│ │ 헤더 (sticky, 52px)      │ │  bg.surface + 하단 1px border
│ ├─────────────────────────┤ │
│ │ 일차 탭 (sticky, 44px)   │ │
│ ├─────────────────────────┤ │
│ │ 뷰 탭 (44px)             │ │
│ ├─────────────────────────┤ │
│ │                         │ │
│ │  콘텐츠 (gutter 16px)    │ │
│ │                         │ │
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

| 항목 | 값 |
| --- | --- |
| 컨테이너 최대폭 | 480px, 가로 중앙 정렬 (태블릿·데스크톱에서 모바일 폭 유지) |
| 좌우 gutter | 16px |
| 카드 세로 간격 | 12px (도보 pill이 끼는 구간은 8px + pill + 8px) |
| 뷰포트 높이 | `100dvh` — iOS 주소창 표시/숨김으로 `100vh`가 튀는 문제 회피 |
| 하단 여백 | `calc(16px + env(safe-area-inset-bottom))` |
| 상단 sticky | 헤더 + 일차 탭까지만. 뷰 탭은 스크롤과 함께 올라간다 |

480px 상한을 두는 이유: 이 UI는 480px 이상에서 카드가 과하게 넓어지면서
정보 밀도가 무너진다. 데스크톱 전용 레이아웃은 만들지 않는다.

## 4.6 컴포넌트 스펙

### 일차 탭 (`1일차 (5/21)`)

| 속성 | 값 |
| --- | --- |
| 높이 | 44px, 균등 분할 |
| 활성 | `label` / `accent.primary` / 700 |
| 비활성 | `label` / `text.secondary` / 500 |
| 인디케이터 | 하단 2px `accent.primary`. 탭 전환 시 `layoutId`로 슬라이드 |
| 미배치 배지 | 18px 원, `danger.solid` 배경, 흰 `badge` 텍스트, 라벨 우측 4px |
| 하단 보더 | 1px `border.default` |

배지 숫자는 **해당 일차의 미배치 후보 개수**로 정의한다(스크린샷의 빨간 `2`).
"할 일이 남았다"는 신호가 탭 자체에 있어야 후보 풀을 열어보게 된다.

### 뷰 탭 (`일정 / 지도 / 비용`)

| 속성 | 값 |
| --- | --- |
| 높이 | 44px, 아이콘 + 라벨 가로 배치 |
| 활성 | `text.primary` 700 + 하단 2px `accent.primary` |
| 비활성 | `text.secondary` 500 |
| 포커스 | `focus.ring` 2px, offset 2px, `radius.sm` |
| ARIA | `role="tablist"` / `role="tab"` + `aria-selected` / `aria-controls` |

| 선택 모드 | 좌측 24px 체크박스 슬라이드 인, 선택 시 보더 `accent.primary` |

### 도보시간 pill

| 속성 | 값 |
| --- | --- |
| 배경 / 보더 | `bg.pill` / 1px `border.default` / `radius.pill` |
| 높이 / 패딩 | 26px / 0 10px |
| 텍스트 | `caption` / `text.strong` |
| 아이콘 | 이동수단별 (`🚶 도보 / 🚇 지하철 / 🚗 자동차 / 🚆 기차`) |
| 배치 | 카드 사이 중앙, 좌우로 1px 점선 `border.subtle` |

보여주면 사용자가 그 숫자를 믿고 일정을 짜다가 현장에서 어긋난다.

이 경로가 훨씬 빠르다.

### FAB

56px 원, `accent.primary`, `shadow.fab`, 우하단 `16px + safe-area`.
랜딩에서는 "여행 추가", 후보 풀에서는 "장소 추가".
`aria-label` 필수 (아이콘만 있으므로).

### 스켈레톤

`border.subtle` → `bg.subtle` 셔머, 1.4s. **실제 카드와 높이가 정확히 같아야 한다.**
어긋나면 콘텐츠가 도착할 때 레이아웃이 튀어 CLS 예산(0.05)을 바로 넘긴다.

### 빈 상태

| 화면 | 문구 | 액션 |
| --- | --- | --- |
| 여행 없음 | `첫 여행을 만들어 보세요` | `여행 추가` 버튼 |
| 후보 풀 비어있음 | `가고 싶은 곳을 모아두면 여기에 쌓여요` | `장소 추가` |
| DAY 비어있음 | `아직 일정이 없어요. 후보에서 가져오기` | 후보 풀 시트 열기 |
| 비용 없음 | `비용을 입력하면 자동으로 합계가 나와요` | `비용 추가` |

## 4.7 모바일 필수 규칙

전역 리셋에 넣는다. 이게 빠지면 어떤 애니메이션을 붙여도 "웹사이트 같다"는 인상이 남는다.

| 규칙 | 이유 |
| --- | --- |
| `touch-action: manipulation` | iOS의 300ms 탭 지연과 더블탭 줌 제거 |
| `-webkit-tap-highlight-color: transparent` | 탭 시 회색 사각형 깜빡임 제거 (누름 상태는 직접 구현) |
| `-webkit-touch-callout: none` (드래그 대상) | 롱프레스 시 시스템 메뉴가 드래그를 가로채는 것 방지 |
| `overscroll-behavior-y: contain` (시트/리스트) | 바운스가 상위 스크롤로 전파되는 것 차단 |
| 최소 터치 타겟 44×44px | 실패 탭 감소. 시각 크기가 작아도 히트 영역을 패딩으로 확보 |
| `100dvh` 사용 | 주소창 표시/숨김에 따른 높이 점프 방지 |
| `env(safe-area-inset-*)` | 노치·홈 인디케이터 침범 방지 |
| hover 전용 어포던스 금지 | 터치에는 hover가 없다. 정보를 hover에만 두지 않는다 |
| 화면 왼쪽 24px에서 수평 드래그 미수신 | iOS Safari 스와이프 뒤로가기 제스처와의 충돌 회피 |

## 4.8 Emotion 구조

```
shared/styles/
├─ tokens.ts            평범한 객체. 위 표의 값 그대로
├─ theme.ts             tokens → Emotion Theme. ThemeProvider로 주입
├─ emotion-provider.tsx 'use client'. useServerInsertedHTML 로 SSR 스타일 삽입
└─ global.ts            리셋 + §4.7 규칙 + CSS 변수 선언
```

- 토큰은 TS 객체로 두고 **타입으로 강제**한다. `theme.color.accent.primary`가 아닌
  하드코딩 hex가 들어오면 리뷰에서 잡는 대신 타입에서 막는다.
- `::view-transition-*` 같은 **React 트리 밖의 의사요소**는 Emotion으로 스타일링할 수
  없다. 이 값들만 `global.ts`에서 CSS 변수로 선언하고 순수 CSS로 다룬다.
- 스타일 충돌은 특이도와 소스 순서로 해결한다. 컴포넌트가 외부에서 `className`을
  받아야 한다면 Emotion의 스타일 합성(`css` 배열 전달)을 쓴다 — 이게
  `!important` 없이 우선순위를 통제하는 정식 경로다.

## 4.9 접근성 체크리스트

| 항목 | 기준 |
| --- | --- |
| 텍스트 대비 | 본문 4.5:1 이상. §4.2에서 미달 2건을 이미 수정 |
| 터치 타겟 | 44×44px 이상 |
| 탭 구조 | `tablist`/`tab`/`tabpanel` + `aria-selected` + 좌우 화살표 키 이동 |
| DnD | dnd-kit 키보드 센서 활성화. 스크린리더 안내 메시지 한글화 |
| 멀티셀렉트 | `aria-multiselectable`, 선택 개수를 `aria-live`로 알림 |
| 지도 | 지도 자체는 보조 수단. **순서 리스트가 동일 정보를 텍스트로 제공** |
| 차트 | 파이차트 옆에 수치 테이블(또는 라벨) 항상 노출 |
| 모션 | `prefers-reduced-motion: reduce`에서 위치 이동 애니메이션 제거 |
| 폼 | 모든 입력에 `label`. 에러는 `aria-describedby`로 연결 |
| 포커스 | `outline` 제거 금지. `focus.ring`으로 재정의 |

지도 뷰에서 스크린샷이 이미 `방문 순서` 리스트를 함께 보여주는 구조인데,
이게 접근성 관점에서 정확한 설계다. 지도만 있으면 그 정보에 도달할 방법이 없다.
